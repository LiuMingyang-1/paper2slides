# Paper2Slides 提示词

提示词源文件由 `npm run prompts` 编译为 `src/prompts/generated.ts`。构建时将公共规则内联，运行时填充变量；应用运行时无需读取 Markdown。修改模板、共享规则或输出预算时，递增所有受影响提示词的版本，确保缓存失效且调用日志可追溯。

| 提示词 | 职责 | 单次输出上限 |
| --- | --- | --- |
| `01-understand.md` | 读整篇证据并提取实际存在的模块。长文先按章节生成短摘要，再合并。各阶段保留原始证据 ID。 | 4,096 tokens；章节及中间合并为 2,048 |
| `02-outline.md` | 按用户侧重点产出 6–10 页，首项为标题页。内容页用具体结论作标题，为已识别的模块写检索意图，并按图注规划原图。 | 1,536 tokens |
| `03-slide.md` | 用检索证据和大纲项填充一页。版式槽位上限由代码注入，按图注匹配原图，每条正文要点带来源和类型，并生成讲稿。 | 2,048 tokens |
| `04-compress.md` | 缩短渲染后指定的溢出槽位。保留要点数量、引用、数字写法、版式及未溢出的内容。 | 2,048 tokens |

四条提示词使用 `language=zh/en`，并各自提供反例。`_shared/citation-rules.md` 约束原文、数字和引用。`_shared/output-schema.md` 约束 JSON 格式。字符串槽位放标签或书目信息，表格正文和关键数字用可核验要点。模型返回不存在但格式正确的证据 ID 时，保留原 ID 并在调用日志记录，由核验环节展示问题。

## 调用估算

6–10 页、无缓存且无重试时，理解与大纲各 1 次，每页 1 次，共 **8–12 次 completion**，总输出预算上限为 **17,920–26,112 tokens**。此前为 7–10 次、13,312–17,920 tokens。按新版模板长度估算，同页输入增加约 300–600 tokens，另加每个可用图约 40–100 tokens 的图注和元信息。正文扩写和讲稿预计令同页实际输出增加约 100–350 tokens，依语言和版式而异。额度预计随页数和 token 增加，具体消耗以平台 `_meta.quotaConsumed` 为准。可选向量检索、长文分章、页面压缩与重试分别计费。

### understand v2（2026-11-20）

- 提示词 ID 与版本：`understand@2`
- 改动、反例与假设：首次真实调用中，模型在模块对象上重复写了 `kind` 键（`{"kind":"problem","points":[…],"kind":"fact"}`），把 point 的 kind 泄漏到模块层。`JSON.parse` 保留最后一个值，导致 6 个模块全部被判为无效并丢弃，整步失败。修复分两层：代码层用"首个键优先"重新解析并记录 normalization（`src/llm/duplicate-keys.ts`）；提示词层明确"模块只有 kind 和 points 两个键，fact/summary/opinion 只用于 point"。
- 论文样本、模型、语言与参数：BERT，`xiaomi/mimo-v2.5`（平台分配），zh，temperature 0.1。
- 指标前后值：v1 理解步骤成功率 0/2（两次运行均失败）；修复后真实原始输出 6/6 模块恢复（回归测试 `src/llm/duplicate-keys.test.ts`）。
- 调用次数、输入/输出 tokens、额度、延迟：单次 15.8k / 1.7k tokens，2.31 额度，约 30s。
- fixture 路径、失败样本与后续动作：`src/llm/fixtures/understand-bert-mimo-v1.raw.txt`。
