## 5. 内容来源测试要点

- **为什么要做**：核验只能证明「PDF 里找得到」，不能证明「是从 PDF 读出来的」。BERT 太有名，模型凭记忆也能写对。
- **篡改实验**：评测脚本生成一份篡改过的 PDF（7 个事实、58 处），走正常上传路径，产品代码里没有任何篡改入口。结果 4 项采用篡改值（70/20/10、GLUE 78.3、SQuAD 91.4、NSP→ASP），0 项回到原值，3 项未出现。人工构造的原值陈述 7 条中 6 条被核验判 ❌。
- **发现的真实局限**（已写进 README）：表格错列时核验仍判 ✅；中文核验偏保守（系统判 ✅ 约 35%，人工复核 72%–81%）。

## 6. 决策

| # | 决策 | 理由 |
|---|---|---|
| D9 | 证明内容来源用「篡改 PDF」而不是在 App 里加篡改开关 | 不污染产品代码，生产包里查无入口 |
| D10 | 核验误判只修通用规则，每个修复配反例 | 核验是卖点，不能为了好看而放松 |
| D11 | README 只写客观、重要的局限，小问题不写 | 用户要求 |
| D12 | 不做与 Anna 官方 PPT 生成器的对比 | 生成一份约 900 积分，性价比低 |

## 7. 教训

- 「harness 没重启所以缓存还在」是我的错误判断，实际每次打开首页都会新建会话。先查清再估额度。
- 测试证明「能用」之后，还要单独证明「内容真的来自输入」，这是两件事。
- 导出的文件要校验到 XML 层面，ZIP 能打开不代表 PowerPoint 能打开。
