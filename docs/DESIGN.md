# Paper2Slides 设计文档

> 状态：设计已定稿，尚未实现。日期：2026-11-20。
> 题目：在 Anna staging 平台交付一个用 AI 制作 PPT 的 Anna App（24 小时）。
> 文中「平台事实」均来自 `staging.anna.partners/llms-full.txt` 官方文档；标注「待验证」的需在开发第一步实测。

---

## 1. 定位

**一句话**：上传一篇论文 PDF，生成**每句话有出处、每个数字经过核验**的组会汇报 PPT。

**目标用户**：研究生、科研人员、读书会。场景是单篇论文精读与组会汇报。

**与 Anna 官方 PPT 生成器的关系**：官方是通用生成器，全流程打通、视觉效果好。我们不在视觉和通用性上与它竞争，而在论文场景的**事实准确性与可追溯性**上做深：

| 维度 | 官方通用生成器 | Paper2Slides |
|---|---|---|
| 输入 | 任意主题 | 单篇论文 PDF |
| 内容来源 | 模型生成 + 可选 Web Research | 仅论文原文 |
| 出处 | 无逐句出处 | 每条要点带原文出处，点击可跳转 PDF 高亮 |
| 数字 | 不核验 | 代码核验：数字必须原样出现在引用的原文里 |
| 结构 | 通用模板 | 按论文实际包含的内容模块组织，缺失不编造 |

README 中将用同一篇论文对比两者输出，列出差异（尤其是数字与出处）。

## 2. 关键设计判断

这一节是本项目的核心，解释「为什么这样做」。

### 2.1 单篇论文不用 RAG 解决「装不下」，而用检索做「约束与核验」

- 一篇论文约 10k–25k tokens，主流模型可整篇放入上下文。**整篇输入**比切块召回更能保留跨章节逻辑（方法 ↔ 实验的对应、消融实验对应哪个模块）。为「用了 RAG」而切碎论文，会损失全局理解。
- 检索真正的价值在三处：
  1. **证据定位**：把模型的陈述锚定到原文段落与页码。
  2. **逐页生成时收窄上下文**：生成某页时只给相关证据块，减少跨页串台与编造。
  3. **核验**：对每条陈述回查原文，判断是否有支撑。
- **边界**：若论文超过模型上下文（学位论文、超长附录），降级为「章节摘要 + 按需召回」。由于 App 无法指定模型（平台使用用户自己选的模型），上下文上限需按 `_meta` 实测并保守设定阈值。

### 2.2 混合检索，按规模选型

- **BM25（关键词）**：数字、数据集名、模型名、指标名等精确词。学术文本中这类词是事实核心，向量检索对它们不敏感。
- **向量检索**：语义类查询（「方法的动机」「局限」）。平台提供 `anna.llm.embed`（独立计费 `APP_EMBED`）。
- **融合**：RRF（Reciprocal Rank Fusion），不需要调两路分数的权重。
- **不用向量数据库**：单篇论文只有几百个证据块，浏览器内存中暴力计算余弦相似度即可。按规模选型，避免过度工程。
- 中文论文：BM25 分词对中文做字符 bigram 处理。

### 2.3 切块按论文结构，而非固定长度

- 层级：章节 → 段落，每块保留 `section_path`（如 `4 Experiments > 4.2 Ablation`）与页码。
- **表格、图注、公式单独成块**（标记类型），便于数字核验与图表引用。
- **剔除**：参考文献、页眉页脚、页码、致谢。参考文献若不剔除，会因标题含关键词而污染召回。
- 过长段落按句子边界二次切分，保留与原段落的关联。

### 2.4 不按「论文类型」分类，而是识别「内容模块」

不给论文贴「方法型 / 综述」这类标签（混合型论文无法归类）。理解阶段让模型标出论文**实际包含哪些模块**：

`problem`、`method`、`theory`、`experiments`、`ablation`、`taxonomy`（综述分类体系）、`limitations`、`future_work`

PPT 结构按实际存在的模块组织。**没有实验就不生成实验页**——从结构上杜绝硬凑内容。

### 2.5 准确性：代码保证，不靠模型自觉

学术汇报最致命的错误是数字错（如把 baseline 结果当成本文结果）。核验全部用确定性代码完成，不消耗额度：

1. **引文核验**：每条要点引用的证据块 ID 必须存在于解析器登记的证据中；要点内容与证据原文做模糊匹配（归一化后 token 重叠 + 最长公共子串）。
2. **数字核验**：要点中出现的每个数字（含百分比、小数、带单位数值），必须**原样**出现在它所引用的证据块里。数字归一化处理 `3.2%` / `3.2 %` / `0.032` 等写法。
3. **三级标注**，不静默删除：
   - ✅ **原文支持**：引用存在、内容匹配、数字全部命中
   - ⚠️ **部分支持**：引用存在但内容为概括，或匹配度低
   - ❌ **无出处**：引用不存在 / 数字不在原文中
4. **陈述类型区分**：每条要点标注 `fact`（原文事实）/ `summary`（模型概括）/ `opinion`（模型评价，如「局限」页的分析）。`opinion` 不要求原文支持，但必须显式标出。

> 注意：有证据 ID ≠ 事实正确。核验能发现「引用不存在」和「数字对不上」，但不能保证语义完全正确；这一点在 README 中如实说明。

### 2.6 排版：模型选版式填内容，代码负责摆放

调研了开源方案：

| 项目 | 做法 | 借鉴点 |
|---|---|---|
| [PPTAgent](https://github.com/icip-cas/PPTAgent)（MIT，EMNLP 2025） | 分析参考 PPT 得到「页面功能类型 + 内容格式」，模型生成编辑动作 | 版式类型 + 内容 schema 的思路 |
| [Paper2Poster](https://github.com/Paper2Poster/Paper2Poster)（MIT） | 渲染后让视觉模型看图回调布局（visual-in-the-loop） | 渲染后检测问题再修正 |
| [anthropics/skills pptx](https://github.com/anthropics/skills/tree/main/skills/pptx) | pptxgenjs + 母版占位符；HTML 测量再转 PPTX | 底层库与避坑清单 |

**共识：没有人让模型直接输出坐标**（不稳定、不可验证）。我们的方案：

1. **预设 6 种学术版式**：标题页、要点 + 图、方法框架图、关键数字（大号数据）、结果表格、对比两栏。每个版式定义若干「槽位」，每个槽位有字数上限。
2. **模型只输出**：版式 ID + 各槽位内容 + 每条要点的证据 ID。
3. **HTML 渲染预览**：每个版式是固定 16:9 尺寸的 HTML 模板，CSS 负责排版。
4. **代码检测溢出**（`scrollHeight > clientHeight`），逐级降级：
   - 缩小字号（不低于下限：正文 14pt、注释 10pt）
   - 仅对该页调用压缩提示词
   - 拆成两页
5. **导出复用测量结果**：读取每个元素 `getBoundingClientRect()`，换算为 pptxgenjs 英寸坐标。**预览与导出同源**，避免「预览正常、导出错乱」。

**本项目的独特优势**：App 本身运行在真实浏览器 iframe 里，可以直接用 CSS 排版和测量，不需要无头浏览器。

### 2.7 引用气泡

- **App 内预览**：类似 ChatGPT 的角标 `[3]`。悬停显示原文片段、页码、核验状态；点击在右侧 PDF 视图跳到对应页并高亮原文（pdf.js 文字层定位）。
- **导出 PPTX**：无法悬停，降级为页面角落小号页码 `p.4`，完整引文写入**演讲者备注**。

### 2.8 论文原图（P0 尝试，失败降级）

- 论文中的图大多是矢量图，直接提取嵌入图片会遗漏。
- 方案：pdf.js 定位 `Figure N` / `Fig. N` / `图 N` 图注文字 → 截取图注上方区域（到上一个文字块为止）→ 高分辨率渲染页面后裁剪。
- 双栏论文按栏宽裁剪；跨栏图按页宽。
- **降级**：截取失败或尺寸异常时，改为文字引用「见原文图 3（p.5）」。不放错误的图。

## 3. 整体流程

```text
① 上传 PDF ──► ② 浏览器解析 ──► ③ 理解论文 ──► ④ 大纲确认 ──► ⑤ 逐页生成
                 (pdf.js)         (AI ×1)        (用户)         (检索 + AI)
                                                                    │
   ⑨ 导出 PPTX ◄── ⑧ 排版检测 ◄── ⑦ 预览 + 气泡 ◄── ⑥ 核验 ◄───────┘
   (pptxgenjs)     (溢出降级)                       (纯代码)
```

| 步骤 | 内容 | AI 调用 |
|---|---|---|
| ① 上传 | 本地选择 PDF，计算 SHA-256 作为缓存键 | 0 |
| ② 解析 | 提取文字与坐标 → 阅读顺序重排 → 结构化切块 → 剔除参考文献 → 截图注区域 | 0 |
| ③ 理解 | 整篇输入，输出元信息、内容模块、各模块要点（带证据 ID） | 1 |
| ④ 大纲 | 基于内容模块生成 5–8 页大纲；用户可选「方法优先 / 实验优先」并调整 | 1（可与 ③ 合并） |
| ⑤ 逐页 | 每页用混合检索取 Top-K 证据块，模型选版式、填槽位 | 每页 1 或批量 1 |
| ⑥ 核验 | 引文 + 数字核验，三级标注 | 0 |
| ⑦ 预览 | HTML 渲染，引用气泡，PDF 跳转高亮 | 0 |
| ⑧ 排版 | 溢出检测与逐级降级 | 0–少量 |
| ⑨ 导出 | 测量坐标 → pptxgenjs → `anna.upload.inline` 获取下载链接 | 0 |

**单篇论文目标 AI 调用次数：3–8 次**（以实测为准，写入 README）。

## 4. 技术架构

### 4.1 平台约束（平台事实）

| 事项 | 平台事实 | 决策 |
|---|---|---|
| App 形态 | `manifest.json` + 静态 SPA，在受限 iframe 中运行 | 纯前端，**不写 Executa** |
| AI | `anna.llm.complete`（输出上限 8192）/ `llm.stream`（65536）；`_meta.quotaConsumed` 返回实际消耗 | 每次调用记录消耗 |
| 模型 | 使用用户在 Anna 中选择的模型，App 不能指定 | 不依赖特定模型能力；JSON 用 schema 校验兜底 |
| 结构化输出 | 插件侧 sampling 支持 `responseFormat`；iframe 侧 `llm.complete` 签名中未列出 | **待验证**；默认按「提示词约束 + 代码校验 + 重试」实现 |
| 网络 | CSP 默认 `connect-src 'self'` | 依赖库全部打包进 bundle，不访问外部域名 |
| 打包 | 允许 html/js/css/json/wasm/图片/字体；**不允许 .md**；总大小 ≤ 50MB | 提示词 markdown 构建时编译为 JS 模块 |
| 存储 | `anna.storage`（KV）、`anna.files`（对象存储） | 缓存解析结果与生成中间状态 |
| 文件下载 | `anna.upload.inline` 返回预签名下载链接 | PPTX 导出路径 |
| Embedding | `anna.llm.embed`，独立计费 | 向量检索 |
| 发布 | 开发者自助激活 → 创建 App（slug 不可改）→ 提交审核 → 管理员批准 | 审核通过前其他账号无法安装 |

### 4.2 模块划分

```text
bundle/
  ui/            页面：上传、解析状态、大纲编辑、预览、PDF 视图、导出
  parser/        pdf.js 封装：文字提取、阅读顺序、切块、图注截图
  retrieval/     BM25、向量、RRF 融合
  llm/           Anna AI 适配：调用、重试、截断检测、消耗记录
  prompts/       （构建产物）由 /prompts/*.md 编译
  schema/        JSON schema 与校验器
  verify/        引文核验、数字核验
  layout/        版式模板、溢出检测、降级
  export/        坐标测量 → pptxgenjs
  store/         缓存与断点续做
prompts/         提示词源文件（markdown）
eval/            评测论文、标注、评测脚本、结果
```

### 4.3 数据结构

```ts
Paper    { id /*sha256*/, title, authors[], pageCount, blocks: Evidence[], figures: Figure[] }
Evidence { id, type: 'text'|'table'|'caption'|'equation', sectionPath, page, text, bbox }
Figure   { id, label /*Figure 3*/, page, captionEvidenceId, imageDataUrl?, cropOk }
Understanding { modules: Module[], meta }
Module   { kind, points: Point[] }
Point    { text, kind: 'fact'|'summary'|'opinion', evidenceIds[] }
Slide    { id, layout, slots: Record<string, Point[] | string>, figureId?, notes }
Verification { pointId, status: 'supported'|'partial'|'unsupported', numberCheck, matchScore }
Deck     { paperId, slides[], verifications[], llmCalls: LlmCallLog[] }
LlmCallLog { promptId, promptVersion, inputTokens, outputTokens, quotaConsumed, latencyMs, stopReason, ok, error? }
```

## 5. 提示词工程

### 5.1 组织

```text
prompts/
├── README.md              # 总览 + 迭代记录（每版改了什么、为什么、指标变化）
├── 01-understand.md       # 理解论文 → 内容模块 + 要点
├── 02-outline.md          # 生成大纲
├── 03-slide.md            # 单页：选版式、填槽位
├── 04-compress.md         # 溢出时压缩单页
└── _shared/
    ├── citation-rules.md  # 引用规则（共用片段）
    └── output-schema.md   # 输出格式说明（共用片段）
```

### 5.2 单个提示词文件格式

```markdown
---
id: slide
version: 3
schema: SlideSchema
maxTokens: 2048
temperature: 0.2
includes: [_shared/citation-rules.md, _shared/output-schema.md]
---
## 角色
## 任务
## 输入
{{outline_item}} {{evidence_blocks}} {{layouts}}
## 规则（硬约束）
## 输出格式
## 反例
```

- 变量用 `{{name}}` 占位，构建时编译、运行时填充；未填充变量直接报错。
- 每次调用记录 `promptId@version`，结果可追溯到具体版本。

### 5.3 迭代闭环

改提示词 → 跑评测集 → 对比指标 → 写入 `prompts/README.md` 迭代记录。
为节省额度：真实 AI 返回存为 fixture，核验/排版代码用 fixture 反复调试；提示词每改一版才重新真实调用。

## 6. 边界条件

| 类别 | 场景 | 处理 |
|---|---|---|
| 输入 | 非 PDF / 损坏 / 加密 | 解析失败即提示原因 |
| | 扫描版（无文字层） | 每页提取字符数过低 → 拒绝并说明（不做 OCR） |
| | 不像论文（无摘要、无参考文献） | 警告，允许用户继续 |
| | 超长（> 40 页） | 提示并只处理正文（参考文献前） |
| | 文件过大 | 设置上限，超限提示 |
| 解析 | 双栏阅读顺序错乱 | 按 x 坐标聚类分栏后重排；已知限制写入 README |
| | 公式乱码 | 公式块标记为 equation，提示词禁止复述公式原文，只描述作用 |
| | 参考文献识别失败 | 退化为按「References」标题截断；失败则保留但降低召回权重 |
| | 中文论文 / 中英混排 | 支持；BM25 中文 bigram |
| 内容 | 无实验 / 无方法 | 按实际模块组织，不生成缺失模块的页面 |
| | 模型引用不存在的证据 ID | 核验标 ❌，预览中显式提示 |
| | 数字不在引用原文中 | 标 ❌，高亮该数字 |
| AI | JSON 格式错误 / 不符合 schema | 带错误信息重试 1 次；仍失败则报错，保留已完成部分 |
| | 输出截断（`stopReason: maxTokens`） | 按页生成，仅重做该页 |
| | 额度不足（`quota_exceeded` / 429） | 调用前估算并展示；失败时提示，已完成结果不丢 |
| | 超时 / 网络错误 | 指数退避重试，上限 2 次 |
| | 论文超出模型上下文 | 降级为章节摘要 + 按需召回 |
| 状态 | 重复点击 / 刷新 | 按 `sha256 + promptVersion` 缓存，不重复扣费；生成中按钮禁用 |
| | 中途关闭窗口 | 每步结果存 `anna.storage`，重开后续做 |
| 输出 | 文字溢出 | 字号降级 → 压缩 → 拆页 |
| | 中文字体缺失 | 指定通用字体（中文：微软雅黑 / PingFang 回退；英文：Calibri / Arial） |
| | 原图截取失败 | 降级为文字引用 |

## 7. 评测

**评测集**：3 篇不同特点的公开论文（提出新方法 / 评测研究 / 综述），各人工标注关键事实与数字。

**指标**：

| 指标 | 定义 |
|---|---|
| 引文有效率 | 引用的证据 ID 存在的比例 |
| 引文支持率 | 核验为 ✅ 的要点比例 |
| 数字准确率 | PPT 中数字与原文一致的比例（人工复核） |
| 关键事实覆盖率 | 人工标注的关键事实被 PPT 覆盖的比例 |
| 排版合格率 | 无溢出页面比例 |
| 成本 | 每篇消耗额度、AI 调用次数、总耗时 |

结果写入 README，并与官方生成器在同一论文上的输出做对比。

## 9. 范围

**P0**：PDF 上传与解析、内容模块识别、大纲确认、逐页生成、引文与数字核验、引用气泡与 PDF 跳转、6 种版式、溢出降级、PPTX 导出、原图截取（失败降级）、缓存续做、调用记录、评测、发布。

**P1**：单页重新生成 / 换重点、演讲者备注扩写、多套配色、渲染截图交给视觉模型检查排版。

**不做**：网页 / arXiv 链接输入、多论文综述、OCR、所见即所得编辑器、动画、Web 搜索补充。

## 10. 开发计划（24h）

| 时间 | 任务 | 验收 |
|---|---|---|
